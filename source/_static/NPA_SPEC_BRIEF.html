NPA 简要技术规格书

Nested Privilege Architecture · v0.3（理论定论摘要）· 配套：SPEC_NPA_CORE / A_D / B / MEM_SEC

一句话 递归特权 = 相对域树上的 call/return；特权在 DCB，执行在 Context；向上只有 ascend。

元原则：宗旨为实现让路；发现漏洞先讨论再修订。

1. 设计宗旨

#原则要点
P1最小概念闭集无明显区别不拆概念，禁驾驶舱
P2一名一义禁双名；传统词只作脚注（syscall/hypercall…）
P3特权 ≠ 执行 ≠ ABIDCB / Context / task_info 分离
P4递归视角无绝对特权层号；不用 Domain N
P5ISA 无关不绑寄存器名 / EL / Ring
P6可执行规范模型可打脸理论

2. 域模型与称呼

        root domain (id=0)
              │
         ┌────┴────┐┐
        hyp(id=1)   ...
            │
           gk(id=2)     δ 视角（在 jit 内）:
            │             δ=0   self = jit
           gu(id=3)       δ=-1  parent = gu
            │             δ=-2  gk
         jit(id=4)
概念记号中文用途
绝对身份id域 ID安全认证 / DMA / 调试；非特权级

禁止：Domain 0/1/−1、用 id 比大小表特权、用 δ 做安全身份。身份看 id，关系看 parent/child，递归看 δ。

3. 原语闭集（A/D 定论）

  parent                         child
    │  alloc DCB + configure       │
    │  descend(dcb)  ────────────► │   first: PC ← entry
    │  (挂起在调用点)               │   resume: PC ← Context
    │  ◄────────  ascend(reason,x) │   回到调用点之后
    │  handle; descend(dcb) ─────► │
    │  ◄──────────── ascend(EXIT)  │   → lifecycle=TERM
    │  reap（父责任）               │

只保留

  • descend(dcb) — 唯一进入形态
  • ascend(reason, x) — 唯一向上原语

reason 闭集

  • SERVICE — 含 syscall/hypercall
  • RESULT — 正常返回
  • EXCEPTION — 同步异常上报
  • EXIT — 结束，不可 resume
不设原因
escalate / return_to_parent / RETURN服务 = ascend + 再 descend
独立 exit 原语ascend(EXIT)
descend(dcb, entry)签名不净；first/resume 仍需状态
手动 MOV LR不自然；返回点硬件自动存
LR 兼 entrysaved_lr 双职回归

first / resume 对软件透明：由 hardware lifecycle 决定。

4. Lifecycle（FREE / LIVE / TERM）

  FREE ──descend(first)──► LIVE ──ascend(EXIT)──► TERM
   ▲                                              │
   └──────────── parent reap / reinit ────────────┘

  descend:  FREE → first (PC←entry)
            LIVE → resume (PC←Context)
            TERM → fault（须 reap）
值descend变迁
FREEfirstcreate / reap
LIVEresume首次 descend
TERM拒绝ascend(EXIT)

lifecycle 是硬件自服务/编程冗余，不是 task state 镜像；放置 DCB/task 由 OS 决定；热路径切换 = 只递 DCB 对象（I20）。

5. DCB Spec Field（10 words / 40B）

off   name   owner    meaning
─────────────────────────────────────
0x00  sz     parent   size in words
0x04  id     system   domain id
0x08  entry  parent   first-PC（仅 first 用）
0x0C  edel   parent   1=子可自管异常，0=一律上交
0x10  exc    child    自管时异常入口（edel=1 且 ≠0）
0x14  irq    system   interrupt handle
0x18  ipa    parent   地址约束表
0x1C  ptb    child    页表基址（0=继承翻译）
0x20  child  parent   当前子域 DCB
0x24  sec    system   安全组 handle
── Impdef 0x28 起（isa 等）──

Context（GPR/PC/SP/flags…）在 DCB 之外，ISA 定义；禁止 saved_* / irq_saved_* 进 Spec。

6. 事件路由

  exception:
    if edel==1 and exc≠0:  本地 exc
    else:                  ascend(EXCEPTION, info)

  irq:   irq 实例 vector（异步，独立）
  fault: 软件分类后走 ascend；非第三硬件入口
edelexc行为典型
0*一律上交隔离 try、严格沙箱
10上交—
1≠0本地；可再 ascendGuest 页错

委托的是「谁收拾残局」，不是「能否越权」——越权必失败（I14）。

7. 地址视图（lazy 内存）

  ┌────────────┬──────────────────────────┬────────────────────┐
  │ ptb / ipa  │ 翻译                     │ ipa 检查对象       │
  ├────────────┼──────────────────────────┼────────────────────┤
  │ 0 / 0      │ 纯继承（同父）           │ 无（同父权限）     │
  │ 0 / ≠0     │ 继承翻译 + 权限覆盖      │ VA                 │
  │ ≠0 / *     │ 子VA→父视图→…→PA（链）   │ 父视图地址(IPA)    │
  └────────────┴──────────────────────────┴────────────────────┘

  access = 翻译 → ipa 权限 → 机密/密钥检查 → 才读写

cache/TLB（后置优化）只加速 page-table hit，不改语义；TLB 须带域标签；机密明文不得因 cache 泄露。

普通 sec机密 csec

10. 核心不变量（I1–I28 选摘）

  1. I1 向上指令仅 ascend。
  2. I2 父恢复点 = descend 调用点之后。
  3. I3/I18 entry 不兼返回点；descend(dcb) 唯一形态。
  4. I4 Spec 无 saved_* / ABI 字段。
  5. I11–I12 ptb=0 不改写父翻译；纯 INHERIT 不宽于父。
  6. I13–I14 edel=0 异常必上交；越权必失败。
  7. I16–I17 安全域 bind 校验绝对 id；TERM 拒 resume。
  8. I19–I20 Spec 不含 task_info；热路径不批量改 DCB。
  9. I23–I25 密钥不进 Spec；csec 被动不可读（含 root）。
  10. I27–I28 可打断不可窥探；csec 伪装 Context。

12. 明确不做（现阶段）

  • TrustZone 式 secure lib 永久链接
  • cache 一致性 / 预取策略（仅约束等价）
  • 密码学算法与 root trust 物理存放（归实现）
  • 侧信道完整防护
  • 旧 pysim 作为目标规格（仅历史证据）
